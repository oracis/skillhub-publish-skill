# WAF 566 命中原理与定位

## 为什么单看报错会走错方向

真实请求是**跨域** `POST https://api.skillhub.cn/api/v1/community/skills/publish`，origin 是 `https://skillhub.cn`。

腾讯云 WAF 命中时会返回 **566 且不带 CORS 头**，浏览器于是报：

```
No 'Access-Control-Allow-Origin' ... net::ERR_FAILED 566
TypeError: Failed to fetch
```

**看到 CORS 报错 ≠ CORS 配置问题**。它只是 WAF 拦截的下游症状，是个披着网络故障外衣的内容问题。

同理，任何 `myqcloud.com` 的 CORS 报错都是噪音——**浏览器不直传 COS**，COS 那条链路与本故障无关。

## 唯一可信的判据

用本机脚本向发布端点 POST 同一份 multipart，看 HTTP 状态码：

| 状态码 | 含义 |
|---|---|
| `401` | 请求已到达**应用层** = 内容安全（只是没登录态，属正常） |
| `566` | 被**腾讯云 WAF** 拦截 = 内容命中规则 |
| 其他 4xx | 业务校验问题（字段/文件类型/slug 冲突） |

这行得通的原因：WAF 拦在应用层之前，所以「能收到 401」等价于「WAF 放行了这份内容」。

## 规则是累计评分制

这是最反直觉、也最容易误判的一点：

- 命中的是**评分**，不是单一关键词。单条危险 token 出现未必触发。
- 危险 token **与代码密度叠加**跨过阈值才 566。
- **推论：单行、单段测过没问题，不代表整个文件安全。必须对完整上传体验证。**

所以「改一处就重新提交」通常仍然 566——因为总分还在阈值之上。

## 实测过的命中特征

> ⚠️ 特征会随 WAF 规则更新而变化，**背特征表不如掌握二分定位法**。以下仅作直觉参考。

- **最高危**：美元符号与双花括号**连写**（GitHub Actions 表达式语法），被当成模板注入 / SSTI 特征。
- **加分项**：形如 `print('..%r..' % (a.get(..), b.get(..)))` 的格式化元组；
  大量 `urllib` / `base64` / `os.environ` / `Bearer` / `token` 等代码 token。

### 规避写法

把美元符号与左花括号之间插一个空格，并在注释里说明「复制到 workflow 时要删掉这个空格」。

**实测无效的做法**（仍 566，别再浪费时间）：
- 加反斜杠转义
- 换成 ERB 风格或百分号风格的模板标签语法（避开字面量，此处不写出具体符号）

### 一个屡次踩中的坑

**连注释里写出那个字面量也算命中。** 写「规避说明」时千万别把危险 token 原样抄进注释。
本技能自己就踩过这个坑——规则文件里描述规则，反而触发了规则。

这也是为什么 `scripts/preflight.py` 对 `SELF_REFERENTIAL`（规则库自身）**跳过 WAF 特征与安全红线检查**：
自指会 100% 误报。

## 定位流程

```bash
python scripts/waf_bisect.py --repo <skill目录> --files SKILL.md manifest.yaml scripts/a.py
```

脚本做三件事：

1. 对**完整上传体**发一次 POST → 打印 `401`（安全）或 `566`（被拦）。这是唯一可信的判据。
2. 逐文件单独发 → 找出是哪几个文件命中。
3. 对命中文件按行 ddmin（delta debugging）→ 输出**最小触发行集合**。

拿到最小集合后改内容，**重跑第 1 步确认全量 401**，再重新打包。

## 排查纪律

- 别去查代理、浏览器扩展、COS、换浏览器——已确认与本故障无关。
- 别凭直觉改一处就打包提交，累计评分制下常常仍 566。
- 定位手法是「按行/块二分 + ddmin」，不是「猜关键词」。
